# (5. lépéshez) GEMINI KVÓTA — mennyi hívás van még ma?
#     A Gemini API NEM adja vissza a maradék napi kvótát (kipróbálva: a Service
#     Usage API 403-at ad API kulccsal, a válaszfejlécekben nincs ratelimit-*),
#     ezért a subtr.py quota HELYBEN könyveli a hívásokat.
py subtr.py quota                 # mai fogyás modellenként
# Opcionálisan:
#   --days 7        utolsó 7 nap
#   --projects      projektmappa szerinti bontás is (hol fogyott el az adag)
#   --model <név>   csak egy modell
#   --where         hol van a napló
#   --reset         mai számlálók nullázása (ha félrement a könyvelés)
#   --forget-limit <modell>   egy megtanult napi limit elfelejtése
#                             (a limitek tartósak, a --reset nem érinti őket)
#
# A napló GÉPSZINTŰ, NEM projektszintű — ez fontos:
#   ~\.gemini_quota\usage.json   (felülírható: GEMINI_QUOTA_FILE env-változóval)
# A napi kvóta az API KULCSHOZ tartozik, nem a mappához. Ha egy gépen több
# felirat-projekt fut ugyanazzal a kulccsal, MIND ugyanabból a napi adagból
# fogyaszt — ezért közös a napló, és a kulcs ujjlenyomata szerint van bontva
# (maga a kulcs SOHA nem kerül a fájlba).
#
# A subtr.py review (gemini ág) és a subtr.py translate --provider gemini
# automatikusan használja:
#   - indulás előtt kiírja, belefér-e a tervezett futás a napi limitbe
#   - minden sikeres hívást könyvel
#   - NAPI limitbe futáskor (429) kiolvassa a tényleges limitet a hibából és
#     elmenti, így onnantól arra a modellre pontos limitet ismer (nem becsül)
#
# A 429 nem mind egyforma! A Gemini percenkénti (RPM) és token-limitre is 429-et
# ad — azok MÚLÓ hibák, a parancsok retry-logikája átvészeli őket. A könyvelés
# ezért a hiba quotaId mezője alapján osztályoz, és CSAK a napi (PerDay) limitet
# tanulja meg. Enélkül egy múló percenkénti hiba (magas --agents értéknél ez
# rutinszerű) rossz napi limitet égetne be, és hamisan "kimerült"-nek jelölné
# a modellt a nap hátralévő részére.
#
# FIGYELEM: a nap NEM helyi éjfélkor vált! A Google ingyenes napi kvótája
# csendes-óceáni idő (PT) szerint nullázódik. A parancs PT szerint könyvel, és
# kiírja, hány óra van a nullázásig.
#
# Tapasztalat: az ingyenes szinten a nem-lite modellek napi limitje 20 kérés
# MODELLENKÉNT (a limit modellenként külön van, ezért modellváltással lehet
# tovább dolgozni). Egy ~400 szekciós rész review-ja 4-5 kérés.
